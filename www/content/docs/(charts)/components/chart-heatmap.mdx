A heatmap answers where something concentrates. Two categorical axes place every cell exactly, and color carries the one value that belongs to that pair — the shape of a week, a season, or a service's bad month, read in one pass.

`heatmapChart` builds the chart from your rows and the fields to read; [`Chart`](/docs/components/chart) renders it in your design system.

## Installation

```npm
npx shadcn@latest add @dotui/chart-heatmap
```

It brings the [`chart`](/docs/components/chart) core along with it.

## Usage

```tsx
import { defineChart } from "@tanstack/charts"

import { Chart } from "@/components/ui/chart"
import { heatmapChart } from "@/components/ui/chart-heatmap"
```

A heatmap reads long rows: one row per cell, with the column field, the row field, and the value. A chart is a figure, so `ariaLabel` is required.

```tsx
const data = [
  { day: "Mon", hour: "09", sessions: 32 },
  { day: "Mon", hour: "10", sessions: 58 },
  { day: "Tue", hour: "09", sessions: 30 },
]

const chart = defineChart(
  heatmapChart(data, {
    x: "hour",
    y: "day",
    value: "sessions",
    label: "Sessions",
  }),
)

export function Example() {
  return <Chart definition={chart} ariaLabel="Sessions by weekday and hour" />
}
```

Both axes are band scales, so the categories appear in the order the rows first mention them — sort your data, and the matrix follows. `label` names what the value means: it titles the legend and labels the value in the tooltip. `labelX` and `labelY` title the two axes, and `formatX` and `formatY` format their labels — and the tooltip title with them.

Cells tile the plot, so there are no gridlines — the cell edges are the grid. Axes and the legend are on by default: the labels are the cells' identity, and the ramp is the only key to the color.

## Color

Color is the whole reading, so it is binned rather than continuous: each bin is a distinct step, and the legend prints the boundaries between them. `colors` is the ramp, low to high, and its length is the number of bins.

```tsx
import { heatmapChart, heatmapColors } from "@/components/ui/chart-heatmap"

heatmapChart(data, {
  x: "hour",
  y: "day",
  value: "sessions",
  colors: heatmapColors("var(--chart-4)", 6),
})
```

`heatmapColors(color, steps)` builds a ramp from one color — `--chart-1` and five steps by default. The low steps fade into the surface and the high steps toward the foreground, so the ramp stays sequential in light and dark without a second set of values. Any array of CSS colors works in its place.

Without `thresholds`, the bins split the observed extent evenly. Pass `thresholds` when the cuts are a policy rather than an extent — one incident is already worth seeing, ten is an outage week:

```tsx
heatmapChart(incidents, {
  x: "week",
  y: "service",
  value: "incidents",
  label: "Incidents",
  colors: heatmapColors("var(--chart-4)", 4),
  thresholds: [1, 4, 10],
})
```

There is always one more color than cut.

## Values in cells

`values` writes each number inside its cell, and `formatValue` formats it — in the cells, the legend, and the tooltip at once. Each label picks black or white from the lightness of the cell under it, so it stays readable at both ends of the ramp.

```tsx
const percent = new Intl.NumberFormat("en-US", { style: "percent" })

heatmapChart(adoption, {
  x: "quarter",
  y: "region",
  value: "share",
  values: true,
  formatValue: (value) => percent.format(Number(value)),
})
```

Only turn it on when the cells are large enough to hold a number — a dozen cells, not a hundred. Everywhere else the tooltip is the place for exact figures.

## Size

`Chart` defaults to a 16:9 box, which stretches the cells of a matrix with few rows. Give it a fixed `height` instead:

```tsx
<Chart definition={chart} height={200} ariaLabel="Monthly rainfall by year" />
```

## Tooltip and focus

Each cell is its own focus stop: hovering or arrowing onto a cell reports that cell alone, titled by its column and row — `15 · Thu` — with one row for the value. The tooltip attaches to the cell rather than to its column.

Both live in the returned spec as `focus` and `tooltip`, so you replace them the same way you extend anything else.

## Composing

`heatmapChart` returns a plain spec, so you extend it like any TanStack Charts definition. To outline one cell, draw a raw `cell` mark over the others — `decorative` keeps it out of the focus order:

```tsx
import { decorative } from "@tanstack/charts/mark/decorative"
import { cell } from "@tanstack/charts/rect"

const heatmap = heatmapChart(data, { x: "hour", y: "day", value: "sessions" })

const chart = defineChart({
  ...heatmap,
  marks: [
    ...heatmap.marks,
    decorative(
      cell([{ day: "Thu", hour: "15" }], {
        x: "hour",
        y: "day",
        fill: "none",
        stroke: "var(--color-fg)",
        strokeWidth: 1.5,
        radius: 2,
        inset: 1,
      }),
    ),
  ],
})
```

## Accessibility

- `ariaLabel` is required and names the figure; add `ariaDescription` when the takeaway needs a sentence.
- The chart surface is in the tab order. Arrow keys move between cells, `Home` and `End` jump to the first and last, `Enter` and Space pin the tooltip, and `Escape` dismisses it.
- A heatmap encodes its measure in color alone, which is exactly the encoding a reader may not perceive. The legend is visual guidance and is hidden from assistive technology, so give the value a `label` and turn on `values` whenever the cells can hold the numbers.
- `tooltip: false` in a definition keeps the focus stops but removes their live region, so screen readers land on silent points. Never turn it off on a heatmap — the tooltip is the only place the exact value is spoken.
