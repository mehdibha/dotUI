A heatmap answers where something concentrates. Two categorical axes place every cell exactly, and color carries the one value that belongs to that pair — the shape of a week, a season, or a service's bad month, read in one pass.

Heatmaps are [`cell`](https://tanstack.com/charts/latest/docs/reference/marks/bar-and-rect) marks rendered by [`Chart`](/docs/components/chart). Copy an example below and change what you need.

## Installation

```npm
npx shadcn@latest add @dotui/chart
```

## Usage

```tsx
import { defineChart } from "@tanstack/charts"
import { colorLegend } from "@tanstack/charts/legend"
import { cell } from "@tanstack/charts/rect"
import { scaleBand } from "@tanstack/charts/scales/band"
import { tooltip } from "@tanstack/charts/tooltip"
import { scaleQuantize } from "d3-scale"

import { Chart, chartLook } from "@/components/ui/chart"
```

A heatmap reads long rows: one row per cell, with the column field, the row field, and the value. Two band scales place the cells, and a color scale bins the value:

```tsx
const data = [
  { day: "Mon", hour: "09", sessions: 32 },
  { day: "Mon", hour: "10", sessions: 58 },
  { day: "Tue", hour: "09", sessions: 30 },
]

const colors = [
  "color-mix(in oklab, var(--chart-1) 20%, var(--surface-bg,var(--color-bg)))",
  "color-mix(in oklab, var(--chart-1) 60%, var(--surface-bg,var(--color-bg)))",
  "var(--chart-1)",
  "color-mix(in oklab, var(--chart-1) 66%, var(--color-fg))",
  "color-mix(in oklab, var(--chart-1) 32%, var(--color-fg))",
]

const chart = defineChart({
  scales: {
    x: { scale: scaleBand },
    y: { scale: scaleBand },
  },
  color: {
    scale: scaleQuantize<string>,
    range: colors,
    nice: true,
    legend: colorLegend({ label: "Sessions" }),
  },
  marks: [
    cell(data, {
      x: "hour",
      y: "day",
      color: "sessions",
      radius: Math.min(chartLook.barRadius, 2),
      inset: 1,
    }),
  ],
  focus: "nearest",
  tooltip: {
    use: tooltip,
    anchor: "point",
    content: (points) => ({
      title: points[0] && `${points[0].datum.hour} · ${points[0].datum.day}`,
      rows: points.map((point) => ({
        label: "Sessions",
        value: String(point.datum.sessions),
        color: point.color,
      })),
    }),
  },
})

export function Example() {
  return <Chart definition={chart} ariaLabel="Sessions by weekday and hour" />
}
```

The categories appear in the order the rows first mention them — sort your data, and the matrix follows. The band scales have no padding: the cells tile the plot, `inset` leaves a pixel between them, and the cell edges are the grid. Cells round their corners with [`chartLook.barRadius`](/docs/components/chart#the-look), up to 2px, so they follow your bars.

## Color

Color is the whole reading, so it is binned rather than continuous: each bin is a distinct step, and the legend prints the boundaries between them. `range` is the ramp, low to high, and its length is the number of bins.

The low steps of the ramp above fade into the surface and the high steps toward the foreground, so it stays sequential in light and dark without a second set of values. Swap `--chart-1` for another series color, or use any array of CSS colors.

`scaleQuantize` with `nice: true` splits the rounded extent into equal bins. When the cuts are a policy rather than an extent — one incident is already worth seeing, ten is an outage week — use `scaleThreshold` and list the cuts in `domain`:

```tsx
import { scaleThreshold } from "d3-scale"

color: {
  scale: scaleThreshold<number, string>,
  domain: [1, 4, 10],
  range: [
    "color-mix(in oklab, var(--chart-4) 20%, var(--surface-bg,var(--color-bg)))",
    "color-mix(in oklab, var(--chart-4) 73%, var(--surface-bg,var(--color-bg)))",
    "color-mix(in oklab, var(--chart-4) 77%, var(--color-fg))",
    "color-mix(in oklab, var(--chart-4) 32%, var(--color-fg))",
  ],
  legend: colorLegend({ label: "Incidents" }),
}
```

There is always one more color than cut. `colorLegend` draws the bins and their boundaries, and `label` names what the value means.

## Formatting

A value prints in up to three places — the legend, the tooltip, and the cells — and each formats its own:

```tsx
const millimeters = new Intl.NumberFormat("en-US", {
  style: "unit",
  unit: "millimeter",
})

legend: colorLegend({
  label: "Rainfall",
  format: (value) => millimeters.format(value),
})

// in the tooltip's content
value: millimeters.format(point.datum.rainfall)
```

`axis: { label: "Hour" }` titles an axis, and `axis: false` hides one.

## Values in cells

Labels are a `text` mark over the cells, wrapped in `decorative` so they never become focus stops. Each label picks black or white from the lightness of the cell under it, so it stays readable at both ends of the ramp:

```tsx
import { decorative } from "@tanstack/charts/mark/decorative"
import { text } from "@tanstack/charts/text"

const shares = data.map((row) => row.share)

// The chart's bins again, so each label knows the color of the cell under it.
const shade = scaleQuantize<string>()
  .domain([Math.min(...shares), Math.max(...shares)])
  .range(colors)
  .nice(5)

decorative(
  text(data, {
    x: "quarter",
    y: "region",
    text: (row) => percent.format(row.share),
    fill: (row) => `oklch(from ${shade(row.share)} calc((0.58 - l) * 100) 0 0)`,
    fontSize: 11,
  }),
)
```

`shade` rebuilds the chart's color scale over the same extent, rounded the same way as `nice: true`. Change one, and change the other.

Only print values when the cells are large enough to hold a number — a dozen cells, not a hundred. Everywhere else the tooltip is the place for exact figures.

## Size

`Chart` defaults to a 16:9 box, which stretches the cells of a matrix with few rows. Give it a fixed `height` instead:

```tsx
<Chart definition={chart} height={200} ariaLabel="Monthly rainfall by year" />
```

## Tooltip and focus

`focus: "nearest"` makes each cell its own focus stop: hovering or arrowing onto a cell reports that cell alone, not its whole column. `anchor: "point"` attaches the tooltip to the cell, and `content` titles it by column and row — `15 · Thu` — with one row for the value. Edit `content` to show other fields of the row.

## Annotations

To outline one cell, draw another `cell` mark over the others. `decorative` keeps it out of the focus order:

```tsx
import { decorative } from "@tanstack/charts/mark/decorative"

decorative(
  cell([{ day: "Thu", hour: "15" }], {
    x: "hour",
    y: "day",
    fill: "none",
    stroke: "var(--color-fg)",
    strokeWidth: 1.5,
    radius: Math.min(chartLook.barRadius, 2),
    inset: 1,
  }),
)
```

## Accessibility

- `ariaLabel` is required and names the figure; add `ariaDescription` when the takeaway needs a sentence.
- The chart surface is in the tab order. Arrow keys move between cells, `Home` and `End` jump to the first and last, `Enter` and Space pin the tooltip, and `Escape` dismisses it.
- A heatmap encodes its measure in color alone, which is exactly the encoding a reader may not perceive. The legend is visual guidance and is hidden from assistive technology, so name the value in the tooltip's rows, and print the values in the cells whenever they fit.
- `tooltip: false` in a definition keeps the focus stops but removes their live region, so screen readers land on silent points. Never turn it off on a heatmap — the tooltip is the only place the exact value is spoken.
