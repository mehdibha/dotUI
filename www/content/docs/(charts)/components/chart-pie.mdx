A pie chart answers one question: how does this total break down? It reads well with a handful of slices and a clear leader, and badly with a dozen near-equal ones — comparing angles is harder than comparing lengths. When the ranking matters more than the share, use a [bar chart](/docs/components/chart-bar).

Pie charts are [`radialArc`](https://tanstack.com/charts/latest/docs/reference/marks/polar) marks inside `polar()`, laid out by `pie()` and rendered by [`Chart`](/docs/components/chart). Copy an example below and change what you need.

## Installation

```npm
npx shadcn@latest add @dotui/chart
```

## Usage

```tsx
import { defineChart } from "@tanstack/charts"
import { pie, polar, radialArc } from "@tanstack/charts/polar"

import { Chart, chartSliceTooltip } from "@/components/ui/chart"
```

One row per slice. `pie()` turns the rows into angles, and `radialArc` draws a slice for each:

```tsx
const data = [
  { browser: "Chrome", visitors: 275 },
  { browser: "Safari", visitors: 200 },
  { browser: "Firefox", visitors: 187 },
]

const chart = defineChart({
  scales: { x: null, y: null },
  marks: [
    polar({
      scales: { angle: null, radius: null },
      radiusRatio: 0.9,
      marks: [
        radialArc(pie(data, { value: "visitors" }), {
          color: "browser",
          stroke: "var(--surface-bg,var(--color-bg))",
          strokeWidth: 2,
        }),
      ],
    }),
  ],
  focus: "nearest",
  tooltip: chartSliceTooltip("browser", "visitors"),
})

export function Example() {
  return <Chart definition={chart} ariaLabel="Visitors by browser" />
}
```

Without x and y scales the chart is square, and arcs carry their own angles, so `polar()` needs no scales either. A slice's x and y are its angle and radius: `focus: "nearest"` focuses the slice under the pointer, and `chartSliceTooltip` names and values it from its own fields.

Slices are drawn in data order, clockwise from twelve o'clock, and take colors from `--chart-1` through `--chart-8` in the same order — sort the rows to change either. A stroke in the page background separates them. Slices read nothing from [`chartLook`](/docs/components/chart#the-look); `Chart` applies its legend placement and motion.

## Donuts

Radii are shares of the chart radius, never pixels, so a pie keeps its proportions at every size. `innerRadius` above zero makes it a donut; `0.55` is a good starting point:

```tsx
radialArc(pie(data, { value: "visitors" }), {
  color: "browser",
  innerRadius: ({ radius }) => radius * 0.55,
})
```

`outerRadius` shrinks the ring the same way, and `radiusRatio` on `polar()` leaves room around the whole pie. `pie()` takes `startAngle` and `endAngle` in radians clockwise from twelve o'clock (`endAngle: Math.PI` draws a semicircle) and `gapAngle` to open a gap between slices. `cornerRadius` on the arc rounds the slices; leaving out `stroke` lets them touch.

## Highlighting a slice

To call out one slice, draw it again over the ring, grown past it. Wrap the copy in `polarDecorative` so it paints without becoming a second focus stop:

```tsx
import { polarDecorative } from "@/components/ui/chart"

const slices = pie(data, { value: "visitors" })

const ring = {
  color: "browser",
  innerRadius: ({ radius }: { radius: number }) => radius * 0.55,
  stroke: "var(--surface-bg,var(--color-bg))",
  strokeWidth: 2,
} as const

marks: [
  radialArc(slices, { ...ring, outerRadius: ({ radius }) => radius * 0.88 }),
  polarDecorative(
    radialArc(
      slices.filter((slice) => slice.browser === "Chrome"),
      { ...ring, outerRadius: ({ radius }) => radius },
    ),
  ),
]
```

To follow a selection, filter by state and memoize the definition over it, as in the [Interactive](#examples) example.

## Labels and center content

Slice labels are `radialText` marks over the same slices. Text is placed through scales, so give `polar()` identity scales: angles in radians, radii as shares of the chart radius.

```tsx
import { pie, polar, radialArc, radialText } from "@tanstack/charts/polar"
import { scaleLinear } from "@tanstack/charts/scales/linear"

const slices = pie(data, { value: "visitors" })

polar({
  scales: {
    angle: { scale: scaleLinear().domain([0, 2 * Math.PI]) },
    radius: { scale: scaleLinear().domain([0, 1]) },
  },
  radiusRatio: 0.9,
  marks: [
    radialArc(slices, { color: "browser" }),
    polarDecorative(
      radialText(slices, {
        angle: "angle",
        radius: 0.72,
        text: "visitors",
        fill: "var(--color-fg)",
        fontSize: 12,
      }),
    ),
  ],
})
```

`text: "browser"` prints the slice names instead, and each slice's `fraction` holds its share of the total, for percentages. `polarDecorative` keeps the labels out of the focus order; the arc beneath them carries the interaction.

The hole in a donut is best filled with plain HTML: `Chart`'s children render over the chart and ignore the pointer.

```tsx
<Chart definition={chart} ariaLabel="Visitors by browser">
  <div className="flex h-full flex-col items-center justify-center">
    <span className="text-3xl font-bold">{total}</span>
    <span className="text-sm text-fg-muted">Visitors</span>
  </div>
</Chart>
```

## Concentric rings

A second series is a second ring, not a stack. Lay out each series with its own `pie()` and draw both arcs in one `polar()`:

```tsx
const ring = {
  color: "month",
  stroke: "var(--surface-bg,var(--color-bg))",
  strokeWidth: 2,
} as const

const chart = defineChart({
  scales: { x: null, y: null },
  marks: [
    polar({
      scales: { angle: null, radius: null },
      radiusRatio: 0.9,
      marks: [
        radialArc(pie(desktop, { value: "desktop" }), {
          ...ring,
          outerRadius: ({ radius }) => radius * 0.6,
        }),
        radialArc(pie(mobile, { value: "mobile" }), {
          ...ring,
          innerRadius: ({ radius }) => radius * 0.7,
          outerRadius: ({ radius }) => radius * 0.95,
        }),
      ],
    }),
  ],
  focus: "nearest",
  tooltip: chartSliceTooltip("month", "value"),
})
```

Both rings color their slices by the same field, so one month is one color from the middle out. `pie()` keeps each slice's size in `value`, so one tooltip reads both rings.

## Legend

`color: { legend: chartLegend }` names the slices below the pie, or wherever your design system puts legends. Lower `radiusRatio` to make room for it:

```tsx
import { chartLegend } from "@/components/ui/chart"

const chart = defineChart({
  scales: { x: null, y: null },
  color: { legend: chartLegend },
  marks: [
    polar({
      scales: { angle: null, radius: null },
      radiusRatio: 0.85,
      marks: [
        radialArc(pie(data, { value: "visitors" }), { color: "browser" }),
      ],
    }),
  ],
  focus: "nearest",
  tooltip: chartSliceTooltip("browser", "visitors"),
})
```

## Accessibility

- `ariaLabel` is required and names the figure; add `ariaDescription` when the takeaway needs a sentence.
- The chart surface is in the tab order. Arrow keys move between slices, `Home` and `End` jump to the first and last, `Enter` and Space pin the tooltip, and `Escape` dismisses it.
- Color alone never carries the distinction — write the slice names into the data so the tooltip names every slice, and add `chartLegend` or name labels to show them without hovering.
- `tooltip: false` keeps the focus stops but removes their live region, so screen readers land on silent slices. Turn it off only for a decorative chart.
