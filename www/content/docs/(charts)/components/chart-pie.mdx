A pie chart answers one question: how does this total break down? It reads well with a handful of slices and a clear leader, and badly with a dozen near-equal ones — comparing angles is harder than comparing lengths. When the ranking matters more than the share, use a [bar chart](/docs/components/chart-bar).

`pieChart` builds the chart from your rows and the fields to read; [`Chart`](/docs/components/chart) renders it in your design system.

## Installation

```npm
npx shadcn@latest add @dotui/chart-pie
```

It brings the [`chart`](/docs/components/chart) core along with it.

## Usage

```tsx
import { defineChart } from "@tanstack/charts"

import { Chart } from "@/components/ui/chart"
import { pieChart } from "@/components/ui/chart-pie"
```

One row per slice. `value` names the field holding the slice size, `name` the field naming the slice. A chart is a figure, so `ariaLabel` is required.

```tsx
const data = [
  { browser: "chrome", visitors: 275 },
  { browser: "safari", visitors: 200 },
  { browser: "firefox", visitors: 187 },
]

const chart = defineChart(
  pieChart(data, {
    value: "visitors",
    name: "browser",
    labels: { chrome: "Chrome", safari: "Safari", firefox: "Firefox" },
  }),
)

export function Example() {
  return <Chart definition={chart} ariaLabel="Visitors by browser" />
}
```

Slices are drawn in data order, clockwise from twelve o'clock, and take colors from `--chart-1` through `--chart-8` in the same order — sort the rows to change either. `labels` names the slices in the legend, the labels, and the tooltip.

## Geometry

Radii are shares of the chart radius, never pixels, so a pie keeps its proportions at every size.

- `innerRadius` above `0` makes it a donut. `0.55` is a good starting point.
- `outerRadius` shrinks the ring inside the chart radius; `radiusRatio` reserves room around the whole pie for labels.
- `startAngle` and `endAngle` are radians clockwise from twelve o'clock. `endAngle: Math.PI` draws a semicircle.
- `padAngle` opens a gap between slices, `cornerRadius` rounds their corners.

Slices are separated by a stroke in the page background; `strokeWidth: 0` lets them touch, and `stroke` changes the color.

```tsx
pieChart(data, {
  value: "visitors",
  name: "browser",
  innerRadius: 0.55,
  strokeWidth: 0,
})
```

`activeIndex` pushes one slice out of the ring by `activeOffset`, to call out the slice the surrounding copy is about. Drive it from state to follow a selection — memoize the definition over it.

## Labels and center content

`sliceLabel` draws text on each slice — `"value"` for the size, `"name"` for the slice name — placed with `sliceLabelRadius` and styled with `sliceLabelFill` and `sliceLabelFontSize`. `formatValue` formats the values, in the labels and the tooltip alike. Slice labels are decorative: they paint but never become keyboard stops or tooltip targets — the arc beneath them carries the interaction.

The hole in a donut is best filled with plain HTML: `Chart`'s children render over the chart and ignore the pointer.

```tsx
<Chart definition={chart} ariaLabel="Visitors by browser">
  <div className="flex h-full flex-col items-center justify-center">
    <span className="text-3xl font-bold">{total}</span>
    <span className="text-sm text-fg-muted">Visitors</span>
  </div>
</Chart>
```

## Concentric rings

A second series is a second ring, not a stack. `pieRing` builds one from its own rows; pass it as the chart's `marks`, which draw inside the pie's polar frame. Give each extra ring its own `id`.

```tsx
import { pieChart, pieRing } from "@/components/ui/chart-pie"

const chart = defineChart(
  pieChart(desktop, {
    value: "desktop",
    name: "month",
    outerRadius: 0.6,
    marks: pieRing(mobile, {
      id: "mobile",
      value: "mobile",
      name: "month",
      innerRadius: 0.7,
      outerRadius: 0.95,
    }),
  }),
)
```

Both rings name their slices by the same field, so one month is one color from the middle out.

## Composing

`marks` takes any TanStack Charts polar mark, so labels the options don't cover are a few lines of the library's grammar. Wrap them in `polarDecorative` so they paint without becoming focus stops:

```tsx
import { pie, radialText } from "@tanstack/charts/polar"

import { polarDecorative } from "@/components/ui/chart"

const percent = new Intl.NumberFormat("en-US", { style: "percent" })

const chart = defineChart(
  pieChart(data, {
    value: "visitors",
    name: "browser",
    innerRadius: 0.55,
    marks: [
      polarDecorative(
        radialText(pie(data, { value: "visitors" }), {
          angle: (slice) => slice.angle,
          radius: () => 0.78,
          text: (slice) => percent.format(slice.fraction),
          fill: "var(--color-bg)",
        }),
      ),
    ],
  }),
)
```

Text and other scaled polar marks read angles in radians and radii as shares of the chart radius. `pieChart` returns a plain spec, so spread it to change anything else — `tooltip: false`, or `motion: false` to repaint without the entrance sweep.

## Accessibility

- `ariaLabel` is required and names the figure; add `ariaDescription` when the takeaway needs a sentence.
- The chart surface is in the tab order. Arrow keys move between slices, `Home` and `End` jump to the first and last, `Enter` and Space pin the tooltip, and `Escape` dismisses it.
- Color alone never carries the distinction — the legend, tooltip, and slice labels all name the slice.
- `tooltip: false` keeps the focus stops but removes their live region, so screen readers land on silent slices. Turn it off only for a decorative chart.
