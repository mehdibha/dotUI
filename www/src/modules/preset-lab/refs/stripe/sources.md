# Stripe: sources

Stripe's design system is Sail. It publishes no tokens as code, but the Dashboard's public bundles carry Sail's palettes and token mapping, and the Stripe Apps docs render Sail's own components. Values come from those computed styles.

## 2026-10-21

`tokens.json` (probe 8eb9b12) and `targets.json` come from public pages and the signed-in Dashboard, light only. Crops of every docs preview and the raw dumps are in the project files under `presets/stripe/2026-10-21/`; the 2026-10-22 capture is under `presets/stripe/2026-10-22/`.

- **Stripe Apps docs** (`docs.stripe.com/stripe-apps/components/*`), public, headless at 1440×900 (`presets:measure --pack stripe`). Each page renders the real Sail components (`[data-testid=stripe-app-example-renderer]`) at Dashboard size; overlays open into `.__sail-layer-containers`. The pages ignore `prefers-color-scheme`, so every page sets `"mode": "light"`.
  - Sizes: buttons, fields and select triggers 28px, 8px padding, 6px corners, 14/20 at 600 (buttons) or 400 (fields); checkbox and radio 14px (checkbox corners 4px); switch 34×18; badges 20px, 12/16 at 400, 6px padding, 4px corners; menus 8px corners, 4px block padding, 32px rows at 14/400 with 10px padding; tooltips a white bubble at 16px padding, 8px corners, 14/20; line tabs 52px at 14/600 with a 2px indicator; table headers 12/700, rows 36–40px with slate-50 hairlines; banners 16px padding, 6px corners, titles 16/700.
  - Edges are box-shadow rings outside the box: `0 0 0 1px` slate-100 #D4DEE9 on secondary buttons, fields, select triggers and checkboxes, and in the fill color on primary buttons. A ring in the fill color draws no line, and the probe ignores it.
  - Shadows: none on buttons and text fields; select triggers and switches `0 1px 1px` rgba(16,17,26,.16); checkboxes and tooltips `0 1px 1px` black 12% + `0 2px 5px` rgba(48,49,61,.08); menus `0 5px 15px` black 12% + `0 15px 35px` rgba(48,49,61,.08).
  - Focus on buttons: `0 0 0 4px` rgba(1,150,237,.36) over the 1px edge ring, so 3px of sky blue past the visible edge.
  - Ink: labels, menu rows and tooltip text in slate-900 #1A2C44; button, field and select ink in slate-800 #273951; List secondary text and the neutral badge in slate-600 #50617A. `text` and `text.muted` now come from the Dashboard.
  - Probe 8eb9b12 adds `field.label` (textfield, 14/600 in slate-900), `radio` and `radio.checked`, `alert` (the neutral banner: white, 1px slate-100, 6px corners) and line tabs (52px at 14/600; `tab`/`tab.selected` now come from the Dashboard, below). The only checked radio on the page is disabled, so `radio.checked` clicks the first radio and reads its `::before`, where Sail paints the blurple dot ring; its `edge` is skipped, since the probe reads the input's slate-100 ring under it. `switch.on` still skips `edge`: its blurple ring in the fill color is read as a line.
  - Caveats: the renderer's root sets #414552 as its own text color, so plain text without a Sail token (List rows) reads in that gray, not Sail's ink. Links and the selected tab compute #5469D4, a docs-only override of the link color (`tab.selected` skips `color`); the Dashboard uses the blurple. `menu` leaves out color, height and font, which belong to its content.
- **dashboard.stripe.com/login**, public, headless at 1440×900. The login form ships the Dashboard's Sail field.
  - A focused login field draws a 1px blurple-300 ring (#a497fc) and a `0 0 0 4px` blurple-100 halo (#e0d9fb), both opaque. Fields inside the Dashboard focus in sky blue instead (2026-10-22, below), so the login page left `targets.json`.
  - The login bundle (`login.*.js`) holds Sail's palettes. Light slate: 0 #ffffff, 25 #F4F7FA, 50 #ECF1F6, 100 #D4DEE9, 200 #BAC8DA, 600 #50617A, 700 #3C4F69, 800 #273951, 900 #1A2C44. Light blurple: 100 #e0d9fb, 300 #a497fc, 500 #675dff, 600 #533afd. Dark slate: 0 #14171d, 25 #1b1e25, 50 #21252c, 100 #2b3039, 700 #a9b2c2, 800 #c9ced8, 900 #eceef1. Dark blurple: 400 #5f4cfe, 500 #746cff, 600 #9289fe.
  - Token mapping (same file): `color.border` slate-100; `color.background.surface` slate-0, `offset` slate-25; `color.text` slate-900; secondary action text slate-800; primary action fill blurple-600; form accent (checks, radios, switches) blurple-500; backdrop slate-200 at 70%.
- **Dark mode** is not measured: no page renders it (see the signed-in pass below). Against the dark palette in the login bundle, the preset's page (#14171d), text and muted text land within ΔE 0.025; control edges sit a step lighter than slate-100.

## 2026-10-21: signed-in Dashboard

Measured in the user's Chrome (Claude in Chrome), test mode in a sandbox account, at a 1512×743 viewport (DPR 2), with the probe's snippet; merged with `--merge … --mode light`. Computed styles of UI chrome only: no page text, no screenshots (the session's safety check refused them).

- Pages (`targets.json`, `"signedIn": true`, no `mode`): `/test/dashboard` (home) and `/test/settings/communication-preferences`. Also walked, not in `targets.json`: `/test/payments`, `/test/settings`, `/test/settings/user`.
- Parts, light: `page`, `shell`, `panel`, `nav.item`, `nav.item.active`, `button.icon`, `link`, `text`, `text.muted`, `command`, `command.item`, `kbd` (home); `tab`, `tab.selected` (settings). These replace the docs readings of `text` and `text.muted`; the docs List and Tabs pages left `targets.json`. The tabs moved to the invoice settings page on 2026-10-22.
- Confirmed on the Dashboard and left on the docs pages: `button.primary` (the sandbox banner's exit button: blurple-600 fill, white 14/600, 28px, 8px padding, 6px corners), `button.secondary` (white, slate-800 ink, 1px slate-100 ring), `checkbox` and `checkbox.checked` (14px, 4px corners, slate-100 ring plus the two-layer shadow; checked blurple-500 #675DFF; both moved to Dashboard pages on 2026-10-22), and the `menu` surface.
- Shell: the sidebar (240px, 20px padding) and the content are both plain white, with no hairline between them; `page` skips `color`, since the root sets #414552 while Sail text uses slate-900.
- Nav: rows 30px, 6px corners, no fill and no padding of their own (the nav pads 20px); 14/400 slate-900, the active row 14/600 in blurple-600 #533AFD with no fill.
- Text: body slate-900 14/400; secondary slate-700 #3C4F69 (`text.muted` reads a 12px timestamp and skips `fontSize`; 14px secondary copy shares the color); chart ticks and footers slate-500 #667691 at 12px. Some older modules still use #414552 and #30313D. Links blurple-600 at 500, so the docs' #5469D4 is confirmed as a docs-only override.
- Icon buttons: the content's secondary icon button is 28×28, white, 1px slate-100 ring, 6px corners. The header's icon buttons are 32px circles, clear, slate-900.
- Tabs: Sail line tabs on Communication preferences are 52px, 12px inline padding, 14/600, slate-700, selected blurple-600 (the invoice settings tabs are 36px, 2026-10-22). Payments' filter tabs are a different 36px pattern: selected slate-900 with a 2px slate-900 bar under the label (a separate `role=presentation` element), no track line.
- Menus: the Create menu (header `+`) matches the docs surface (white, 8px corners, 1px slate-100 hairline, `0 5px 15px` black 12% + `0 15px 35px` rgba(48,49,61,.08), 4px block padding) and 32px rows with 10px padding and 3px corners, but its rows are blurple-600 actions, so `menu.item` stays on the docs' slate-900 reading.
- Search (`command`): a 604px popover with the menu shadow, 8px corners and a 2px slate-25 rim; rows 28px, 8px corners, `4px 8px` padding on an inner element (`command.item` skips padding and the inherited #414552 color); a slate-25 footer.
- `kbd` (the `?` shortcuts drawer): legacy gray #EBEEF1, 3px corners, 20px, 6px padding, Menlo 13/500 in #414552. The drawer opens from the left, 530px, right corners 6px, with the menu shadow.
- Caveats: `button.primary` exists only in a sandbox (its banner), and `text` reads the setup guide, which only new accounts show. The Language select on `/test/settings/user` draws no edge or fill (a quiet trigger), so `select.trigger` stays on the docs. No dialog was found to open without creating something (Create customer opens one, 2026-10-22).
- **No dark appearance:** the Dashboard has no theme setting (Personal details lists only Language; the account menu has none) and ignores `prefers-color-scheme` (the OS was dark, the Dashboard rendered white), so there is no dark pass and nothing to restore.

## 2026-10-22: signed-in forms, dialog and table

Captured by the user in a local Claude Code session (research Chrome over CDP, 1440×900 at DPR 2), sandbox in test mode, light only, with the probe's snippet; merged with `--merge … --mode light`. Nothing typed, saved or submitted. Crops of UI chrome are in the project files; full-page shots stay on the user's machine.

- Pages (`"signedIn": true`): `/test/settings/billing/invoices/general` (`tab`, `tab.selected`, `radio`, `radio.checked`, `switch.on`, `input.focus`, `button.focus`), the same page past one `PageDown` (`#payment-page`: `input`, `select.trigger`, `checkbox.checked`, `switch.off`), and `/test/customers` (`dialog`, `checkbox` in the Create customer dialog). They replace the docs readings of every form control and of both focus parts; the docs Select, Checkbox, Switch and Radio pages left `targets.json`. Opening the dialog's Shipping information section saves `expanded-edit-customer-modal-invoicing-fields-shipping-information` in `localStorage`: remove it after a run.
- Form controls match the docs: fields and select triggers 28px, 8px padding, 6px corners, slate-100 ring (select triggers add the `0 1px 1px` drop, at 600); checkbox and radio 14px; switch 34×18, off on slate-50 #ECF1F6 inside the slate-100 ring, on blurple-500.
- Focus: buttons and fields alike take the 3px sky blue ring (rgba(1,150,237,.36), read as #A3D9F9 on white) 1px out; a focused field keeps its slate-100 edge. `button.focus` reads the Edit button, a secondary, so it skips `edge` (the specimen focuses a primary).
- Tabs: the invoice settings tabs are 36px, 12px padding, square, 14/600 in slate-700, the selected one blurple-600 over a 2px blurple bar (a separate `role=presentation` element, 52×2). Each tab has a `::after` inset 4px with 8px corners, probably its hover fill. With Payments' 36px filters, 36px is the common height; Communication preferences' 52px tabs are the exception.
- Dialog (`.__sail-layer-containers [role=alertdialog]`): white, 8px corners, slate-900 ink, no hairline (the ring layer is transparent), `0 5px 15px` black 12% + `0 15px 35px` rgba(48,49,61,.08), the menu shadow. Backdrop rgba(186,200,218,.7), no blur. Field labels in the dialog are 14/500 in #1A1B25.
- `field.label` stays on the docs: Sail settings forms hide their field labels, and the visible ones are legacy (`settings.row-label` 14/600 #414552 in the left column; one Sail label above a control renders its text in a legacy 14/500 #414552 span).
- Table (Radar › Lists, the sandbox's only non-empty table; survey only, not a probe part): 36px rows, 14/400 #545969 cells padded 8px (20px on the first column), `inset 0 1px` #EBEEF1 hairlines, inside a white card with 6px corners and a 1px #EBEEF1 ring. Page titles are 28/36 at 700 in #30313D.
- Customers' filter chips are 38px with 8px corners, 14/600 slate-900, the selected one in a 2px slate-900 border.
